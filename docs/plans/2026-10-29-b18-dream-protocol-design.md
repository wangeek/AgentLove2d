# B18 LLM 生成协议（dream）设计提案（送审稿 v1）

> 状态：**设计提案——待用户人工审阅**。整合：B13/B18 构想（LLM 凭空生成）、
> token 经济测算（400 tok/s 约束）、ev 打断-重生成工作流（用户描绘）、
> 状态快照命题关闭（§5.2）、B15/B18 冲突裁决（2026-10-29）。

## 0. 一句话

LLM 当导演、结算器当摄影机：**LLM 说语义层 delta（什么发生了），确定性结算
器展开行级流（每一笔怎么画）**——token 预算只为叙事密度付费，行级簿记由代码
承担。

## 1. token 经济（为什么必须分层）

- 行级直出不可行：稳态帧 :px 形态 ≈ 数千 token/帧，400 tok/s 下 1 帧 >10s；
- 语义层可行：**26 token/帧预算恰好卡进 15fps 验证档**（26×15=390 ≤ 400）；
  0.5ms 首 token ⇒ 交互延迟可忽略；idle 态 `same` 零 token 续航（成本曲线与
  叙事强度对齐——静态世界 0 token，打斗密集）。

## 2. 与 B15 的冲突裁决（本轮核心结论）

**冲突**：B15 的增量词汇是"推导物"（生产者持全量行集，delta 由 diff 构造，
正确性由构造保证）；B18 若让 LLM 直接书写 paramdelta，则要求 LLM 跨长上下文
精确簿记行身份 (asset,k)——精确状态追踪正是 LLM 弱项（幻觉形态：引用不存在
的行号/对已删行发 delta/k 序错乱；fr-lint 只能拦语法错，拦不住语义错）。

**裁决：三层分工钉死**——

```
LLM（导演）：语义层 delta —— "hero.x += 120"、"敌人入场@(5,3)"、"镜头切城门"
    ↓ 确定性结算器（通用规则库/游戏内核）：唯一持有行身份簿记的角色
FR 流：paramdelta/rowdelta/same —— B15 词汇表原样（传输/存储编码定位）
    ↓ 回放器
画面
```

- B15 spec 显式决策：增量词汇表=传输/存储编码，**不按 LLM 可书写性设计**；
- B18 核心交付 = **语义 delta schema + 通用结算器接口**（非复用 B15 行语法）；
- LLM 幻觉防线在语义层：fr-lint 语义规则（状态 schema 校验）+ 结算器防御
  （出界钳制/非法动作拒绝）。

## 3. ev 打断-重生成工作流（用户描绘的协议化）

```
连续生成（LLM 按 token 预算吐语义 delta → 结算器展开 → 流追加）
  → 用户 ev 到达 = 分叉点：当前链封存（append-only，不丢弃）
  → ev 注入 LLM 上下文（流前缀摘要 + 最近语义 delta 窗口）
  → LLM 重新生成 → 新链续写
  → 输出完自然断流（开放会话：append-only，随时接续）
  → idle：same 零 token 续航 / 静态帧声明
```

- **打断 ≠ 队列追加，是分叉**：事件帧 = delta 链开链点（与 B15 checkpoint
  落事件边界同一结构——存储侧与生成侧共用骨架）；
- **接续 = 读前缀流/投影摘要**（§5.2 已裁定：流是唯一持久化物，无序列化器）；
- **上下文管理** = 滑动窗口（最近 K 帧语义 delta）+ 周期投影摘要——投影格式
  是 B18 的真设计点（见 §5）。

## 5. B18 真设计点（两项）

1. **语义 delta schema**：LLM 的创作语言。形态候选：a) 状态键值 delta
   （`hero.x=120`——紧、确定性高）；b) 意图语言（"英雄向城门移动"——富表达
   但需结算器内嵌解释器）。**建议 a 起步 b 演进**（a 的结算器=通用物理/绘制
   规则库；b 的解释器是 a 之上的规则层，非替换）。
2. **前缀投影格式**：喂 LLM 的状态摘要（多长历史/什么粒度/st 行还是语义
   schema）——纯消费端工具，与 §5.2"接续=读前缀流/摘要"一致。

## 6. 边界与不做

- 不做状态图序列化（§5.2 已裁定伪命题）；
- LLM 不直接书写行级 delta（§2 裁决）；
- 不做"通用游戏引擎"——结算器规则库按 dream 场景最小集起步（移动/绘制/
  碰撞可选），按实测叙事需求增补（YAGNI）。

## 7. 验收线（PoC 级，B13-dream）

- ✅ LLM 循环跑通：st 投影注入 → 语义 delta 输出 → 结算器展开 → 流追加 →
  fr-render 出画面，连续 ≥60 帧无 lint 失败
- ✅ ev 打断：注入点击 → LLM 上下文更新 → 生成响应包 → 流分叉点标记正确
- ✅ idle 续航：无输入 30 帧，流仅追加 same 行（token 消耗 0）
- ✅ 判据：每帧经 fr-lint 语义层 + 结算器防御（出界钳制）
