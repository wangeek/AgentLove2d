# 架构决策台账

> 本项目一切设计往上追溯的根，与 FR 规格（docs/fr-spec.md）配套。修订方式：追加新条目并注明取代关系，不改旧条目正文。

## D1 中间表示按 LLVM IR 模式做（2026-10-25 用户拍板）

**定论**：两个世界之间的中间物，语义唯一、编码两种、每步可观察、判据锚定关键行。四条款：

1. 双形态——二进制流给机器、文本 dump 给人，`llvm-as/dis` 式一键互转工具落地（约定靠工具不靠文档），互转本身进回归（round-trip 压漂移）；
2. 每变换步骤后可 dump（`opt -print-after-all` 式），diff 相邻阶段定位 bug；
3. 判据锚行不锚全文（FileCheck 式 CHECK 行），判据不含不稳定成分；
4. 命令表 = 单一真源数据，两端编解码代码从表生成（TableGen / wayland-scanner 式），账本驱动升格为生成源。

**适用边界**：中间物是长期契约 + 要长期回归 + 两端异构才值得；一次性中间数据不套。

**背景**：DeepSeek 分享对话延伸讨论；用户批概念堆砌、要 Unix 哲学朴素语言。渲染分离 = 无头内核输出行式 display list，渲染端是消费者（终端转义 / GCC IR / PostScript 同构）；事件 = 不插入、进队、帧末出队（Erlang mailbox / WAL / Quake .dem 同构）。

## D2 绘制原子语义四准则（2026-10-26 定稿）

1. **命令流只流通符号不流通场数据**——像素先落成有编号的资产、命令引用编号。界碑：X11 `CreatePixmap`+`CopyArea`（正）对 `PutImage`（反）；汇编指令对 `.byte` 块；NES OAM（1983）；DOOM vislist（1993）。
2. **原子 = 谓词 + 参数**，效果 = f(帧内可见状态, 参数) 纯函数、行自解释。
3. **命令集大小由原版频度表决定**，不由 API 手册决定（GDI ROP 256 种，实收小集）。
4. **行自描述优先于带宽**，裁剪/翻转做参数，唯一全局态独立成帧头行。

## D3 验证两律（2026-10-26 定稿）

1. 每环验证只许落在**符号比较**（锚行 diff）或**字节相等**（定长资产比对）上；资产级计算（矩阵 diff / 掩码 / 相交 / 校验和）由配套小脚本承担，AI 调脚本读结果——没有人"理解"像素，只有脚本"计算"像素。
2. **符号层 = 日常回归**（高频锚行查逻辑），**像素层 = 终审**（低频整帧定长 BMP 字节相等查视觉）。

## D4 结构归属：树不进协议（2026-10-26 定稿）

父类 / 容器 / 局部坐标在内核端结算成**绝对坐标**，协议只收扁平行。树可作被引用的内容（CAD block 式：定义一次、引用多次），不可作执行上下文（X11 窗口树 + Expose 为反面；NeWS 语义进协议为坟头；Dear ImGui 立即模式为正面）。

内核端三层，各带 dump 点，切分三类错误：

```
UI 结构层（控件、父子、局部 rect——逆向自原版窗口/控件布局）
  ↓ dump① 控件表 —— 对拍原版结构，错 = 逆向错
扁平化结算（树走一遍：局部→绝对坐标，viewport org / clip 展开成参数）
  ↓ dump② 结算表 —— 错 = 结算错
display list（行行自解释）
  ↓ dump③ 命令流 —— 错 = 编码错
```

调试信息进 dump 注释列，不进协议（DWARF 式旁路）。hit test = 结算表上的矩形相交查询，绘制与事件两个方向共用同一张结算表。

## D5 语境纪律：设计对象 = 现代语义，legacy 只做兼容投影（2026-10-25 用户两次批评后定）

语义层一律用现代语境（浮点坐标、RGBA、光栅字体、HID scancode、UTF-8）；legacy（GDI / ROP / VK_ / WM_ / 点阵 / 调色板）只能作为**前端降级（lowering）规则表**存在，绝不进入 IR 词汇表。用户原话："我们最终还是要面对现代场景，对 GDI 只是有办法兼容就可以。"

- 错误形态：把取证对象当设计对象——IR 说方言（SPR 带 PAL 号 / 整数坐标 / VK_ 事件），等于 clang 把 C 的 int 塞成 IR 类型。
- 配套：忠实性由 lowering 规则表（gdi_map.tsv）保证；调色板离线展开成 RGBA 资产，lut 动画为唯一方言特例；浮点确定性：`%.6f` 定长、锁 IEEE、判据优先锚整型 + 校验和。

## D6 LÖVE 定位：参考渲染器，不是内核的家（2026-10-26 定）

LÖVE 是 display list 的第一个消费者 / 实验床；无头内核独立（独立进程或线程）。逻辑一旦钻进 `love.update`，无头内核名存实亡——这是纪律问题。锁版本 11.5，升级当一次显式迁移。它上不了裸机的地方恰是流协议的主场：设备端瘦客户端与 LÖVE 消费同一份流，互为对拍。

## D7 工程纪律（贯穿）

- 判据不含不稳定成分；墙钟只进注释列。
- 工具 / 接口命名：不与现成 shell 命令撞语义（screen→draw 教训），看名知意，一般人也看得懂。
- 块 = 编号矩阵资产，分辨率无关；透明 / 碰撞是资产级矩阵计算，脚本完成、字节相等验收。
- 每批收尾先问"这批是否新造了会影响别处的耦合"——是则当场做掉（依赖优先，欠账不得后置）。

## D8〔待拍板 2026-10-26〕魔改宿主架构（提出即取代 D6 的"外部消费者"定位）

前提修正（用户纠偏）：本项目先建 FR 工具链，载体=魔改 LÖVE；内核是跑在其 Lua VM 上的脚本；sango 是未来 lowering 前端之一，与本项目解耦。

1. **捕获层在 C 包装边界**（w_* 入口，fr-gen 从 cmd.tbl 生成），栈上实参拷贝成记录、按 section 列路由——一机制覆盖 in/log/out 三段；对象参数只记资产号。
2. **绘制生产消费者=引擎内 C 回放器**（解码后直调 Graphics::draw 系）；**捕获后回放**：内核模式 love.graphics.* 只记录不执行，present 后回放上屏——视觉真源唯一=IR。另留一个 Lua 消费者作契约证人。
3. **事件捕获/注入在 C**（Event::pump 单咽喉 + w_push）；编排=自有 run loop（帧首排干快照再分发——poll 中途 push 落帧由构造定义；CALL 深度在此记录）。
4. **log=VM 外机制（PG WAL 同构）**：A 堆镜像 diff 主力（LuaJIT gc.root 全对象链 + 影子副本 memcmp 出脏槽位 → st 物理行，同次遍历产 s_crc；full 级专用，off/base 不碰堆）+ B 字节码写拦截第二批（TSET handler/trace store IR 下插，O(变动数) 真 WAL）；路径=消费端 logical decoding（登记表：对象→路径，随 checkpoint 周期重发；登记项带 epoch 与首末帧——防 GC 指针复用的幽灵路径，checkpoint 全量重推校正）。Lua 侧树遍历已否决（过 Lua C API，帧预算击穿）。rngc 仍为边界捕获；debug 栈钩仅限 fr-trace 审计；内核 RNG 统一走 love.math.random。
5. 纪律承 D6 精神：内核与渲染的唯一通道是 FR 流；内核不得读渲染端状态。

取证细节见 docs/love2d-gap.md v2。
